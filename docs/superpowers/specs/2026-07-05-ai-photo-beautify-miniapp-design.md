## 一、产品概述

### 1.1 产品定位

一款基于 AI 模型的微信小程序，用户上传照片后由 AI 自动美化处理，预览免费、下载付费。通过代币体系实现商业变现。

### 1.2 目标用户

全人群覆盖 — 日常自拍、旅游照、社交媒体素材、创意玩法。

### 1.3 核心差异化

- 预览免费、下载才扣费，降低用户尝试门槛
- 代币体系灵活：注册送币、购买、订阅每日领、活动送、邀请返利
- 后台填表式配置，非技术人员可独立维护

## 三、功能模块

### 3.1 用户端功能

#### 3.1.1 美化处理

四大分类，用户上传图片后选择效果，AI 处理完成后展示水印预览，下载时扣费。

| 分类 | 子功能 | 说明 | 建议定价 |
|------|--------|------|---------|
| 👤 人像美化 | 磨皮美肤、智能美白、瘦脸塑形、大眼亮眼、祛痘去皱 | 针对人物照片 | 2-3 代币 |
| 🎨 色彩画质 | 智能调色、滤镜风格、清晰度增强、去雾除噪、光影优化 | 提升照片观感质感 | 1-2 代币 |
| 🎭 风格转换 | 动漫风、油画风、水墨风、素描/线稿风、像素风 | 创意玩法 | 3-5 代币 |
| ✨ 一键美化 | AI 自动分析照片选择最优方案 | 兜底懒人方案 | 2-3 代币 |

#### 3.1.2 处理流程

```
用户上传图片
      ↓
选择美化类型 + 参数
      ↓
云函数接收 → 查询 model_configs 获取当前启用 API
      ↓
调用 AI 模型处理
      ↓
生成两张图：
  · 预览图（加水印）→ 云存储
  · 原图（无水印）→ 云存储
      ↓
返回预览图展示  ← 不扣费
      ↓
用户操作：
  ├── 不满意 → 重新选择效果（回到选择步骤），不扣费
  └── 满意 → 点击下载
             ↓
         校验代币余额
           ├── 不足 → 提示充值
           └── 充足 → 扣费 → 返回原图 → 记录流水
```

#### 3.1.3 历史记录

- 已处理图片列表，支持再次下载（已付费图片不重复扣费）
- 可重新处理同一原图选择不同效果

#### 3.1.4 个人中心

- 代币余额展示
- 代币充值入口（套餐列表 → 微信支付）
- 订阅管理（订阅状态、每日领取按钮）
- 交易流水明细
- 邀请分享入口

### 3.2 代币体系

#### 3.2.1 代币来源

| 来源 | 类型 | 过期规则 |
|------|------|---------|
| 注册赠送 | 永久 | 不过期 |
| 购买套餐 | 永久 | 不过期 |
| 订阅每日领取 | 永久 | 不过期 |
| 邀请奖励（双方） | 永久 | 不过期 |
| 活动赠送 | **限时** | 活动结束后过期清零 |

#### 3.2.2 消费规则

- 预览免费，下载无水印原图才扣费
- 不同美化分类不同定价（后台可配）
- 扣费优先级：查询 `user_activity_tokens`，按 `expires_at` 升序，先扣最早过期的限时代币，限时代币耗尽后再扣永久代币（`users.tokens`）

#### 3.2.3 订阅制

- 按月订阅（价格后台可配）
- 订阅期间每日登录可领取固定数量代币（数量后台可配）
- 每日限领一次，当天未领视为放弃，不累计

#### 3.2.4 活动代币过期

- 每日凌晨云函数定时扫描 `user_activity_tokens`
- 找出 `expires_at < now` 的记录，汇总每个用户的总过期代币数
- 扣除 `users.activity_tokens`，删除/归档 `user_activity_tokens` 中已过期记录
- 记录 `expire` 流水
- 微信模板消息提醒用户（可选）

### 3.3 邀请返利

#### 3.3.1 规则

```
用户A 分享小程序给 用户B
         ↓
用户B 首次进入并注册
         ↓
绑定邀请关系
         ↓
用户B 首次完成下载付费
         ↓
   ┌────┴────┐
   ↓         ↓
邀请人A    被邀请人B
+永久代币   +永久代币
(后台可配)  (后台可配)
```

- 仅新用户（首次注册）可被邀请
- 每个新用户只能绑定一个邀请人
- 邀请奖励在**被邀请人首次付费后**发放
- 奖励为**永久代币**，不过期

### 3.4 管理端功能

通过账号角色判断（`role: 'admin'`）进入管理端，所有配置即时生效。

#### 3.4.1 模型配置

- 按美化分类分组展示（人像美化 / 色彩画质 / 风格转换）
- 每分类支持多个模型供应商，启用/禁用一键切换
- 添加/编辑模型：厂商名称、API 地址、API Key、额外参数(JSON)
- **一键测试连通性**：发测试图验证 API 是否可用
- 切换即时生效，无需重启

#### 3.4.2 活动管理

- 活动列表：名称、奖励代币数、有效期、状态
- 创建活动：名称、描述、赠送代币数、开始/结束时间
- 支持手动启用/停用/编辑

#### 3.4.3 定价管理

- 每种美化分类的下载扣费代币数（人像/色彩/风格/一键）
- 编辑即时生效

#### 3.4.4 代币套餐管理

- 套餐列表：名称、价格、代币数、赠送数、上架状态
- 编辑即时生效

#### 3.4.4 订阅配置

- 月费价格、每日领取代币数
- 微信订阅消息模板 ID 配置

#### 3.4.5 邀请返利配置

- 被邀请人奖励代币数
- 邀请人奖励代币数
- 发放条件（固定：首次付费后）

#### 3.4.6 数据面板

- 当日处理量、收入、活跃用户数
- 基础统计（MVP 阶段）

## 五、云函数设计

### 5.1 云函数列表

| 云函数 | 功能 | 触发方式 |
|--------|------|---------|
| `processImage` | 调用 AI 模型处理图片，生成预览图和原图 | HTTP 调用 |
| `downloadImage` | 校验代币、扣费、返回无水印原图 | HTTP 调用 |
| `getPresignedURL` | 获取云存储临时下载链接 | HTTP 调用 |
| `createOrder` | 创建充值订单，返回微信支付参数 | HTTP 调用 |
| `paymentCallback` | 微信支付回调，确认到账 | HTTP 回调 |
| `dailyCheckIn` | 订阅用户每日领取代币 | HTTP 调用 |
| `claimActivity` | 用户领取活动代币 | HTTP 调用 |
| `checkInvite` | 注册时检查邀请参数，绑定邀请关系 | HTTP 调用 |
| `expireTokens` | 扫描 `user_activity_tokens` 中过期记录，清零限时代币 | 定时触发器（每日凌晨） |
| `syncOrders` | 扫描 pending 订单，查询支付状态补单 | 定时触发器（每 5 分钟） |

### 5.2 模型调度层设计

`processImage` 云函数中的模型调度逻辑：

```
1. 接收参数：图片 fileID、分类 process_type、子类型 sub_type
2. 查询 model_configs：
   - 匹配 category = process_type
   - 筛选 is_active = true
3. 取第一个启用模型（或随机负载均衡）
4. 构造请求（统一抽象）：
   {
     image_url: <云存储临时链接>,
     task_type: sub_type,
     ...config 中的额外参数
   }
5. 调用 API，获取结果图
6. 生成预览图（加水印/压缩）+ 原图 → 存入云存储
7. 写入 images 表，返回预览图 fileID
```

**切换模型机制：**
- 管理员在后台切换启用模型，更新 `is_active` 字段
- 下次调用 `processImage` 时自动使用新模型
- 无需重启、无需重新部署

## 六、错误处理

| 场景 | 处理方式 |
|------|---------|
| 图片格式不支持 | 上传时校验，仅允许 jpg/png/heic/webp |
| 图片过大 | 单张限制 10MB，超出提示压缩 |
| AI 处理失败 | 不扣费，提示重试；连续失败记录日志 |
| API 超时 | 云函数 30s 超时，返回 processing 状态让前端轮询 |
| 代币不足 | 下载时弹窗引导充值 |
| 支付异常 | 回调失败保持 pending，定时任务补单 |
| 网络中断 | 已扣费可在历史记录重新下载，不重复扣费 |
| 模型 API 不可用 | 后台一键切换备用模型 |
| 活动代币到期 | 定时扫描清零，推送提醒 |

## 七、MVP 范围

### ✅ MVP 包含

- 四大分类美化处理（人像 + 色彩画质 + 风格转换 + 一键美化）
- 预览免费、下载付费
- 代币体系：注册送、购买、订阅、活动、邀请
- 微信支付（代币套餐购买）

- 管理端：模型配置、活动管理、套餐定价、邀请配置、基础数据面板

- 批量处理

- 社区/分享广场/排行榜
- 多语言
- 详细数据分析（仅基础面板）
- 图片去重

## 八、设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 技术栈 | 微信云开发 | 免运维、快速上线、与微信生态原生集成 |
| 模型方案 | 腾讯云 API + 抽象调度层 | MVP 快速验证，后期可替换 |
